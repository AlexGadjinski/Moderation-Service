# Riplio — Moderation Service

Content-moderation microservice for **Riplio**. It handles content reports and moderation decisions, and is consumed by the Riplio main backend.

> **Repository:** https://github.com/AlexGadjinski/Moderation-Service

This is a standalone microservice. It works together with the Riplio main backend — see [Related repositories](#related-repositories).

## Responsibilities

- Persists and manages content **reports** and their lifecycle (`PENDING`, `DISMISSED`, `CONTENT_REMOVED`).
- Exposes moderation endpoints consumed by the main backend.
- Provides a **health** endpoint used by the main backend's scheduled health check.
- Secured for service-to-service calls with a shared **internal API key**.

## Tech stack

- Java 21, Spring Boot 3.4.0 (Web, Data JPA, Validation)
- MySQL
- Lombok
- Maven
- Testing: JUnit, Spring Boot Test, JaCoCo (coverage), Checkstyle

## Getting started

### Prerequisites

- Java 21
- Maven 3.9+
- MySQL 8+

### Environment variables

Set these before running. **Do not commit real values** — use your local environment or an untracked `.env` file.

| Variable | Description |
|----------|-------------|
| `DB_USERNAME` | MySQL username (e.g. `root`) |
| `DB_PASSWORD` | MySQL password |
| `INTERNAL_API_KEY` | Shared key used to authenticate requests from the main backend (must match the value configured in the backend) |

Example (replace with your own values):

```bash
export DB_USERNAME=root
export DB_PASSWORD=your_db_password
export INTERNAL_API_KEY=your_internal_api_key
```

On Windows PowerShell:

```powershell
$env:DB_USERNAME="root"
$env:DB_PASSWORD="your_db_password"
$env:INTERNAL_API_KEY="your_internal_api_key"
```

### Database

Create the database before first run:

```sql
CREATE DATABASE riplio_moderations_service;
```

Schema is managed by JPA/Hibernate on startup.

### Run

```bash
./mvnw spring-boot:run
```

The service starts on `http://localhost:8081` with a base path of `/api/v1`.

### Test

```bash
./mvnw test
```

Coverage reports are generated by JaCoCo under `target/site/jacoco`.
